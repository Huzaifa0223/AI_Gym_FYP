## 1. `/api/score` request handler today (`api_backend.py:555–659`)

```python
@app.post("/api/score", response_model=ScoreResponse)
async def score_video(
    video: UploadFile = File(...),
    exercise: str = Form(...),     # validated against app_config.EXERCISES
    age_group: str = Form(...),    # validated against app_config.AGE_GROUPS
) -> ScoreResponse:
```

Pipeline composition is **inline** in the handler:

1. Enum validation (`exercise`, `age_group`) — 400 on mismatch.
2. Content-type check — 415 if not `video/*`.
3. Body read + size cap (50 MB) — 400 on empty, 413 on overflow.
4. Inline pipeline:
   ```python
   with VideoProcessor(exercise) as vp:
       counter = make_rep_counter(exercise, age_group)
       scorer  = FormScorer(exercise, age_group)
       for pf in vp.process_bytes(video_bytes):
           if not pf.landmarks_detected:
               continue
           event = counter.update_angle(pf.primary_angle, pf.timestamp,
                                        features=pf.features)
           if event is not None:
               score = scorer.score(event)
               rep_results.append(_to_rep_result(event, score))
   ```
5. Aggregate `average_score` from per-rep `final_score` floats.
6. Return `ScoreResponse(exercise, age_group, total_reps, average_score,
   frames_processed, frames_with_landmarks, processing_time_s, reps)` —
   `headline` field omitted (defaults to `None` per Stage 1's optional
   field).

**Implication for 5c:** The pipeline is loose composition, not a class.
Per the Phase 1 brief ("ScoringPipeline class … if extracted per
audit"), the cleanest move is to extract it into `core/pipeline.py` so
the new `headline`-populating path is unit-testable in isolation. In-place
extension would couple Stage 5c's tests to a FastAPI handler.

**Decision:** extract `ScoringPipeline` to `core/pipeline.py`. Leave
`/api/score` as a thin FastAPI shim that builds a `ScoringPipeline`,
calls `.score(video_bytes, exercise, age_group)`, and adapts the
result to `ScoreResponse`.

## 3. FSM phase names (`core/rep_counter.py:44–50`)

```python
class RepState(Enum):
    IDLE = auto()
    DESCENDING = auto()
    BOTTOM = auto()
    ASCENDING = auto()
    TOP = auto()
```

Five phases. Reference-skeleton schema needs one `frames` entry per
non-`IDLE` phase (4 entries) — `IDLE` is the pre-rep waiting state and
has no canonical pose. The placeholder JSON should include exactly
`DESCENDING / BOTTOM / ASCENDING / TOP`.

## 4. `app.state` and lifespan

* `app.state` — **not currently used** anywhere. `grep app.state api_backend.py` returns no matches.
* `@app.on_event("startup")` / `@app.on_event("shutdown")` — **not used**.
* `@asynccontextmanager` — **not used**; ExerciseManager is constructed eagerly at module import (`api_backend.py:310 exercise_manager = ExerciseManager()`).
* FastAPI version: **0.104.1** (per `pip show fastapi`). Supports the
  `lifespan=` constructor argument (added in 0.93+).

**Implication for 5c:** Add a `@asynccontextmanager async def lifespan(app)`
that initialises `app.state.equipment_holder`, `app.state.frame_buffer`,
`app.state.cnn_lstm_scorer`, `app.state.threshold_provider`, and
`app.state.equipment_task` (async background task). On shutdown it
sets the stop event and awaits the task. Pass `lifespan=lifespan` to
the `FastAPI(...)` constructor. Keep the existing `exercise_manager`
global for now to avoid disturbing `/api/process-frame` — that
endpoint is out of 5c scope per the Phase 1 brief and migrating it
would balloon the diff.

## 5. Demographics handling

* **Age group** — derived from `request.age` (per-frame endpoint) or
  passed directly as a `Form` field (`/api/score`). Mapped via
  `age_to_group(age)` in `config.py` or the inline branches in
  `ExerciseManager.get_exercise_instance` (`api_backend.py:280`).
* **`user_height_cm`** — Stage 1's `LandmarkFrame` schema carries this
  field (`Optional[float]`). It is **not** currently accepted by any
  HTTP endpoint, **not** propagated through `VideoProcessor`, **not**
  used by anything that calls into `utils.normalization`.
  `compute_body_segment_unit` falls back to the shoulder/hip-width
  derivation on every call.
* **5c posture:** continue to leave `user_height_cm` unwired. The
  Stage 3 calibrator CLI accepts it as a `--user-height-cm` flag but
  the API does not. Surfacing it through `/api/score` would expand
  scope; not in the Phase 1 brief. Tag as a future follow-up if the
  CNN+LSTM stage needs height-normalised inputs.

## 8. Items flagged for the design pass that follows this audit

Inputs to the Stage 5c implementation, captured here so they don't
get lost:

1. Extract pipeline to `core/pipeline.py`. Don't extend in place.
2. Use FastAPI 0.104's `lifespan=` arg, not the older `@on_event`
   decorators (deprecation warnings).
3. Reference skeleton schema: 4 phases (skip `IDLE`).
4. Feature `headline` population: re-derive `rep_count` from
   `total_reps`; map `final_score` average → `score`; `form_feedback` =
   first `violations[].message` of any rep, else `""`; `source_breakdown`
   = `{"rules": rule_score_int, "rf": rf_score_int_or_None,
   "cnn_lstm": None}`. (CNN+LSTM is null per `NullFormQualityScorer` until
   weights ship.)
5. Graceful degradation: missing `.pkl` → `rf_score=None` already
   handled by `MLAggregator` raising and `FormScorer` catching.
   Missing thresholds → `ThresholdsNotFoundError` mapped to **422**
   in the new endpoint, not 500. Missing reference skeleton → 404.
6. Equipment endpoint: should return 200 with the `EquipmentState`
   sentinel (`detections=()`, `last_updated_frame_id=-1`,
   `last_updated_timestamp_ms=-1`) **not** 0/0 — matches the Stage 4
   sentinel value documented in `EquipmentState` docstring.
7. The equipment background task expects a `frame_source` callable.
   `/api/score` is one-shot (single video upload, not a continuous
   stream), so the production `frame_source` for 5c is the
   `LatestFrameBuffer` populated by the per-frame endpoint
   (`/api/process-frame`). When the buffer is empty, `frame_source`
   returns `None` and the background loop skips that cycle. The
   background loop runs continuously regardless — it does not require
   `/api/score` to be active.
