## 2. Pydantic v2 models used by `/api/score`

Defined in `api_backend.py` (lines 122–185):

```python
class ViolationResult(BaseModel):
    name: str
    severity: Literal['minor', 'major']
    message: str
    penalty: float

class RepResult(BaseModel):
    rep_number: int
    start_ts: float
    end_ts: float
    duration_s: float
    peak_angle: float
    trough_angle: float
    ml_score: Optional[float] = None      # NaN -> null
    ml_confidence: Optional[float] = None  # NaN -> null
    rule_penalty: float
    final_score: Optional[float] = None    # NaN -> null
    violations: List[ViolationResult]

class ScoreResponse(BaseModel):
    exercise: str
    age_group: str
    total_reps: int
    average_score: Optional[float] = None  # None when no reps with final_score
    frames_processed: int
    frames_with_landmarks: int
    processing_time_s: float
    reps: List[RepResult]
```

Adapters:

- `_nan_to_none(value: float) -> Optional[float]` — JSON has no NaN literal, so `math.isnan` values become `null`.
- `_to_violation_result(v: FormViolation) -> ViolationResult`
- `_to_rep_result(event: RepEvent, score: FormScore) -> RepResult`

Request side: `video: UploadFile`, `exercise: Form(...)`, `age_group: Form(...)` — validated against `app_config.EXERCISES = ['bicep','back','chest']` and `app_config.AGE_GROUPS = ['children','adult','senior']`. HTTP error mapping: 400 (bad enum / empty / undecodable / no frames), 413 (>50 MB), 415 (non-`video/*` content-type), 500 (uncaught).

Note: `ExerciseRequest`/`ExerciseResponse` (lines 69–105) belong to `/api/process-frame`, not `/api/score`. They are still Pydantic v1-style (`@validator('frame_data')`); migration to v2 `@field_validator` is a known follow-up but not part of the 3-Pillar scope.

## 3. Rule-engine + ML-aggregator structure

### 3.1 Rule engines (`core/rule_engine.py`)

- All concrete engines inherit `BaseRuleEngine` and implement `evaluate(rep: RepEvent) -> list[FormViolation]`.
- Universal helpers (in the base class) consume only `rep.peak_angle`, `rep.trough_angle`, `rep.duration_s`, and `rep.trajectory`:
  - `_check_rom(rep, min_range)` → 'rom_short' (major, 15 pts).
  - `_check_speed(rep, min_s, max_s)` → 'too_fast' (minor, 5) or 'too_slow' (major, 15).
  - `_check_tempo_stability(rep, max_cv)` → 'jerky_tempo' (minor, 5) on `std/mean` of frame deltas.
  - `_check_tempo_symmetry(rep, min_ratio, max_ratio)` → 'tempo_asymmetry' (major, 15) using trough-index split.
- Exercise-specific overrides (call universal + own checks):

| Engine | Universal checks invoked | Exercise-specific checks (use `feature_history`) |
| --- | --- | --- |
| `BicepRuleEngine`  | rom (80°), speed (1–5 s), tempo stability | _none yet — comments mark elbow drift / torso swing as TODO_ |
| `BackRuleEngine`   | rom (80°), speed (1–5 s), stability, symmetry | `_check_scapular_retraction` (secondary < 50° at peak; major 15), `_check_torso_stability` (secondary std < 15°; major 15) |
| `ChestRuleEngine`  | rom (60°), speed (0.8–4 s), stability, symmetry | `_check_plank_integrity` (mean secondary ≥ 165°; major 15), `_check_leg_alignment` (mean tertiary ≥ 170°; major 15) |
| `NullRuleEngine`   | _none_ — always returns `[]` (fallback for unknown exercise) |

Factory: `make_rule_engine(exercise) -> BaseRuleEngine` looks up `_ENGINE_CLASSES = {'bicep': …, 'back': …, 'chest': …}` and falls back to `NullRuleEngine`.

### 3.2 ML aggregator (`core/ml_aggregator.py`)

- `MLAggregator(exercise, age_group)` calls `_load_model(model_path(exercise, age_group))` from `config.py`. `model_path()` resolves to `data/models/{exercise}_{age_group}.pkl`.
- `_load_model` opens the file with raw `pickle.load` (project convention is "load via `joblib.load()`; never use `pickle.load()` directly in production code" — see CLAUDE.md §10. **Discrepancy noted; not changed in this audit phase.**). It accepts either a bare estimator or a `dict` with key `'model'` (the project convention).
- `score(rep)`:
  1. Raises `InsufficientDataError` if `rep.feature_history` is empty.
  2. Stacks `[primary_angle, secondary_angle, tertiary_angle]` rows into an `(N, 3)` `float64` array.
  3. Trims columns to `model.n_features_in_` if the trained model expects fewer than 3 features (defensive — no padding to grow).
  4. Calls `predict_proba(features_2d)`. `good_idx = min(1, probas.shape[1] - 1)` so single-class models do not crash.
  5. Returns `(mean(good_probs) * 100, mean(max(probas, axis=1)))` — `(ml_score, confidence)`.

### 3.3 Hybrid combination (`core/form_scorer.py`)

| ML available | Rules available | `final_score` |
| --- | --- | --- |
| ✅ | ✅ | `clamp(ml_score - rule_penalty, 0, 100)` |
| ✅ | ❌ (Null) | `ml_score` |
| ❌ | ✅ | `clamp(100 - rule_penalty, 0, 100)` |
| ❌ | ❌ | `NaN` |

`FormScorer.__init__` swallows `ModelNotAvailableError` and logs a warning; rule engine always succeeds via `NullRuleEngine` fallback. `_rules_available` is `not isinstance(self._rule_engine, NullRuleEngine)`.

## 6. Items flagged for Phase-2 design to address

These are observations only — the audit does **not** propose fixes:

1. **`pickle.load` in `core/ml_aggregator.py`** vs. CLAUDE.md §10 rule "Load via `joblib.load()`; never use `pickle.load()` directly in production code." Discrepancy predates 3-Pillar scope.
2. **Two parallel angle APIs** — `utils/angle_utils.calculate_angle_3d` (returns `float`) is what the new `core.*` pipeline uses; `utils/pose_utils.calculate_angle_3d` (returns `AngleResult`) is what `exercises/bicep_curl.py` falls back to. `bicep_curl.py` is also the only exercise class **not** inheriting `BaseExercise`. 3-Pillar architecture should decide whether the legacy `bicep_curl` path is in or out.
3. **Pydantic v1-style validator** in `ExerciseRequest.validate_frame_size` (`@validator('frame_data')`). Pydantic v2 is in `requirements.txt` per CLAUDE.md §2. `/api/score` models already use plain v2 fields.
4. **`MLAggregator` silently trims** feature columns to `model.n_features_in_`. If 3-Pillar adds new features, consumers need to know that an old 3-feature model will see only the first three columns, not the new ones.
5. **`BicepRuleEngine` exercise-specific rules are still TODO** (per the docstring at `core/rule_engine.py:225`). Back and Chest engines are populated; Bicep is not.
6. **No `.pt` ignore rule** in `.gitignore`. If 3-Pillar lands YOLOv8 weights, that needs adding to keep the repo lean.
7. **`docs/` did not exist** before this audit — created by writing this file.
